演習トップ ／ MiniKGのSPARQL例

自分のKGを検索する
SPARQLテンプレート集

簡易RDF-DBを開く ／ MiniKG.ttl（確認用）

課題（目安15分）
必須：T1・T2。標準：さらにT3～T5から1つ以上。発展：独自のクエリを作る。

使い方

  1. 自分のTTLを簡易RDF-DBに読み込む。
  2. RDF変換画面の述語変換表、またはRDFの内容から実際のプロパティ名を確認する。
  3. テンプレートを選び、自分のKGの図から結果を予想する。
  4. クエリをコピーしてDBに貼り付け、黄色の箇所を書き換えて実行する。
  5. 質問・変更箇所・予想・クエリ・結果を記録する。

標準のIRI設定、IRI自動生成、rdfs:label出力、rdf:Property出力を前提とします。人物名はRDFのラベルと完全に一致させてください。

T1：特定の関係を持つノードの組T2：特定の人物に関する情報一覧T3：特定の人物と指定した関係を持つノードT4：同じ関係先を持つ人物T5：2つの関係をたどった検索

T1：特定の関係を持つノードの組 必須

質問例：友人関係にある人物の組は？
応用例：師弟関係、所属組織の一覧

変更箇所：friend を自分のKGのプロパティ名に変更する。

PREFIX prop: <http://example.com/prop/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?name1 ?name2 WHERE {
  ?x prop:friend ?y .
  ?x rdfs:label ?name1 .
  ?y rdfs:label ?name2 .
}

MiniKGでの結果例（3件）
name1name2
太郎次郎
太郎花子
花子次郎
結果の順序は不定。日本語ラベルは @ja 付きです。

T2：特定の人物に関する情報一覧 必須

質問例：太郎から出る関係とその関係先は？
応用例：主人公の仲間・所属・役職など

変更箇所：太郎 を自分のKGの人物名に変更する。@ja は残す。

PREFIX prop: <http://example.com/prop/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?relation ?name WHERE {
  ?x rdfs:label "太郎"@ja .
  ?x ?p ?y .
  ?p rdfs:label ?relation .
  ?y rdfs:label ?name .
}

このクエリは主語から出る関係のうち、述語と目的語にラベルがあるものを取得します。逆向きの関係は対象外です。

MiniKGでの結果例（4件）
relationname
友人次郎
友人花子
所属A研究室
指導教員田中先生
結果の順序は不定。日本語ラベルは @ja 付きです。

T3：特定の人物と指定した関係を持つノード 選択

質問例：太郎の指導教員は誰か？
応用例：主人公の仲間、人物の所属先

変更箇所：太郎 と supervisor を変更する。

PREFIX prop: <http://example.com/prop/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?name WHERE {
  ?x rdfs:label "太郎"@ja .
  ?x prop:supervisor ?y .
  ?y rdfs:label ?name .
}

MiniKGでの結果例（1件）
name
田中先生
結果の順序は不定。日本語ラベルは @ja 付きです。

T4：同じ関係先を持つ人物 選択

質問例：同じ研究室に所属する人物の組は？
応用例：同じ師匠、同じ出身地

変更箇所：affiliation を2か所とも同じプロパティ名に変更する。

PREFIX prop: <http://example.com/prop/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?name1 ?name2 ?common WHERE {
  ?x prop:affiliation ?z .
  ?y prop:affiliation ?z .
  ?x rdfs:label ?name1 .
  ?y rdfs:label ?name2 .
  ?z rdfs:label ?common .
  FILTER (?x != ?y)
}

FILTERで同一ノードの組を除外します。A・BとB・Aの両方が得られます。

MiniKGでの結果例（2件）
name1name2common
太郎花子A研究室
花子太郎A研究室
結果の順序は不定。日本語ラベルは @ja 付きです。

T5：2つの関係をたどった検索 選択

質問例：友人とその友人の所属先は？
応用例：親の親、師匠の所属先

変更箇所：friend と affiliation を自分のKGの連続する関係に変更する。

PREFIX prop: <http://example.com/prop/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?name1 ?name2 ?name3 WHERE {
  ?x prop:friend ?y .
  ?y prop:affiliation ?z .
  ?x rdfs:label ?name1 .
  ?y rdfs:label ?name2 .
  ?z rdfs:label ?name3 .
}

2つの矢印が同じ中間ノードでつながる部分を探します。

MiniKGでの結果例（3件）
name1name2name3
太郎次郎B研究室
太郎花子A研究室
花子次郎B研究室
結果の順序は不定。日本語ラベルは @ja 付きです。

検索結果が0件・エラーの場合

  • 自分のTTLを読み込んだか、全トリプル検索で確認する。
  • プロパティ名の大文字・小文字、PREFIX、人物名と @ja を確認する。
  • 矢印の向きと、指定したグラフパターンが実際に存在するかを確認する。
  • T2で0件の場合は、出ていく矢印がある人物を選び、述語と目的語のラベルを確認する。
  • T4・T5に一致する構造がない場合はT3を選ぶか、出典に基づいてKGを拡張する。

提出内容

テンプレート番号、自然言語の質問、変更箇所、予想した結果、実行したSPARQL、実際の結果と予想との差を記録する。
